# DMS Agent 放心、准确、智能、美观、速度迭代路线

> 日期：2026-08-05  
> 范围：独立 UI、DMS 首页嵌入、企业微信三端共用同一问数与知识库内核。  
> 原则：不另起平行系统；权限、口径、SQL 闸门、执行器继续只有一个事实源。

## 1. 调研结论

同类产品的共同方向不是让大模型自由写更多 SQL，而是把大模型放在受治理的语义层和执行工具之上：

1. **Snowflake Cortex Analyst**：语义模型负责业务定义；Verified Query Repository 用人工验证过的问句与 SQL 提高相似问题准确率和可信度。
2. **Databricks Genie**：用受 Unity Catalog 治理的数据、指标、业务规则、样例查询和 verified answers 构造领域 Agent。
3. **Looker**：LookML 把维度、指标、关联和权限变成可复用语义资产，问答与报表共同消费同一模型。
4. **Power BI / Fabric**：强调先为 AI 整理语义模型、组织说明和示例；Agent 仍受底层权限与治理策略约束。
5. **Tableau Pulse**：围绕“指标定义”主动给出趋势、驱动因素、目标和异常，而不是只返回查询结果。
6. **ThoughtSpot Spotter**：关系搜索模型提供业务上下文，支持 coaching、复杂分析计划、结构化与非结构化联合分析。
7. **SuperSonic**：Chat BI 与 Headless BI 共用语义层；schema mapper、规则/LLM 双解析、corrector、translator 分工明确。
8. **SQLBot**：工作区与数据权限隔离、术语/提示词/SQL 样例配置、可视化分析和多入口嵌入形成完整产品闭环。
9. **Deep Agents**：subagent、checkpoint、持久记忆、上下文压缩和 approve/edit/reject 是深度任务可靠运行的关键；安全依赖工具边界，不能依赖模型自律。
10. **DataNote**：预览页、用户选择卡、分析产物、经验复盘、日报调度把一次回答扩展成可继续操作和分享的工作成果。

结论：DMS Agent 的下一阶段应从“能查、能出深度页”升级为**可信的语义分析操作系统**。确定性系统负责权限、口径、计算与证据；大模型负责理解、规划、解释、复盘和交互。

## 2. 当前基线与核心缺口

| 方向 | 已有基础 | 当前最重要缺口 |
|---|---|---|
| 放心 | DMS 身份继承、`ScopedSql`、行权限注入、敏感列脱敏、只读源、会话归属、分享产物 | 用户看不到统一的可信凭证；缺少反馈、争议复核、质量看板和答案置信分级 |
| 准确 | 指标/维度/值域/关联/快照注册表，确定性路由，SQL 校验与修复，66 条回归、39 条评测 | 长尾名词和单号类型覆盖不足；指标缺版本/生效期/允许下钻维度；批准样例尚未形成强 VQR 闭环 |
| 智能 | 六段路由、深度 PLAN、AI 分析、会话改写、经验与语义召回 | PLAN 仍偏“生成几个子问题”；缺少问题分类、证据检查、可暂停恢复、结构化澄清和结果自审 |
| 美观 | KPI、图表、表格、深度 artifact、预览/分享/下载 | 缺少统一报表语法、目标/对比/异常/驱动布局；部分页面仍由文本主导，跨端视觉质量未形成门禁 |
| 速度 | 确定性快路、语义缓存、并行深度子查询、热切换 | 缺少结果集缓存、查询取消、渐进式返回、分路由 SLO、慢查询归因与热点预热 |

内部判断：当前“已登记场景”较强，主要风险集中在**未登记长尾、歧义问题、深度报告关联性和可观测闭环**，不应继续只靠增加提示词解决。

## 3. 目标架构

一次问答固定经过下面六层，三端只负责展示和身份承接：

```text
身份与权限 -> 问题理解 -> 语义编译 -> 可信执行 -> 分析规划 -> 报表与证据
                 |            |            |            |
              实体/单号     指标/维度/VQR  ScopedSql    ReportSpec
              歧义选择      Join Graph     校验复核     Artifact
```

### 3.1 可信答案协议

在现有 `AskResult` 增加可选 `trust`，不改变老调用方：

- `level`：`verified`（已验证）、`high`（高可信）、`review`（需确认）。
- `metric_version`：指标版本与生效时间。
- `source/freshness`：数据源、数据截至时间、快照时间。
- `time_window/caliber`：实际计算时间窗与业务口径摘要。
- `scope`：是否受当前 DMS 账号的数据权限约束。
- `evidence`：来源表、行数、SQL 指纹、校验器结论、是否截断/脱敏。
- `confidence_reasons`：只列可验证事实，不输出模型“自信度”。

置信分级由路由确定性、映射歧义、口径命中、SQL 规则、执行结果形状、数据新鲜度和 VQR 命中共同计算；LLM 不得直接给自己打高分。

### 3.2 语义编译器

继续使用现有 `meta.metric/dimension/join_edge/value_map/sql_exemplar`，不新建第二套语义层：

- 指标增加版本、生效期、负责人、允许维度、默认时间粒度、质量状态。
- `sql_exemplar` 升级为 VQR：只有审核通过、无敏感实体、执行回归通过的样例才能参与高权重召回。
- 映射顺序固定为：精确别名 -> 业务字典 -> 值域反查 -> 向量召回 -> LLM 候选；多候选不可静默猜测。
- 派生指标支持递归展开、环检测、分子分母时间窗一致性和格式继承。
- Join Graph 增加基数、有效条件、时间字段、明细表/主表角色和来源代码证据。
- 单号/名称建立 `EntityResolver`：格式特征、业务前缀、候选表、主明细关联、唯一性探测统一注册。

### 3.3 深度分析协议

将 `deep_api` 中的自由板块生成收敛成 `AnalysisPlan -> ReportSpec`：

- `AnalysisPlan`：问题类型、主指标、时间窗、比较基准、分析维度、明细对象、风险检查。
- `ReportSpec`：标题、KPI、趋势、构成、驱动、异常、明细、口径、AI 收尾；每块声明证据查询和可视化类型。
- 已知指标由模板化分析合同决定最少内容；LLM 可以选择和排序，不得发明指标、维度或计算值。
- AI 分析必须位于数据证据之后，默认压缩为“结论 / 异常 / 建议”三组短卡，展开后才显示详细说明。
- 每条 AI 结论必须关联上方 KPI、图表点或表格行；无法引用证据的句子不进入报告。

### 3.4 深度 Agent 运行时

借鉴 Deep Agents/DataNote，但保持现有单管线：

- 计划、执行、复核分离；每个 subtask 只能通过现有 `ask()`，不得直接执行自由 SQL。
- 增加 checkpoint、取消、恢复和会话切换后台继续执行；状态按 `conv_id + request_id` 隔离。
- 歧义问题返回结构化选择卡；用户选择后从 checkpoint 恢复，不重新跑已完成步骤。
- 对高风险查询支持 approve/edit/reject；只允许用户编辑语义选择和筛选条件，不允许绕过权限闸门。
- 长结果进入 artifact/文件系统，Agent 上下文只保留摘要和引用，避免 prompt 膨胀。

## 4. 五条专项路线

### 4.1 放心

1. 前端结果顶部统一显示“已验证口径 / 当前账号权限 / 数据截至 / 可核查 SQL”状态条。
2. 新增答案反馈：正确、口径不对、数据不全、权限问题、展示问题；自动绑定 trace、SQL 指纹和指标版本。
3. 高价值指标支持双路径核对：确定性模板与 VQR/语义编译结果按关键值比较，不一致则降级为“需确认”。
4. 分享页默认带数据源、时间、生成者、权限范围和有效期；支持撤销，禁止分享绕过原会话权限。
5. 增加权限红队：DMS Java 权限等价、跨账号、跨角色、跨会话、缓存污染、分享 token 五组测试。

### 4.2 准确

1. 从 DMS 后端 Mapper/Service/Enum/VO 自动抽取表用途、单据前缀、状态码和关联，再由人工审核进入图谱。
2. 从 Doris 其他业务库只抽取元数据与公共维度模式，用于识别命名规律；任何 DMS 指标不能因为同名跨库自动套用。
3. 建立“问题 -> 语义 IR -> SQL -> 结果摘要”黄金集，P0 业务逐题保存执行级期望，不只比较 SQL 文本。
4. 对指标做维度合法性检查、扇出检查、时间上限检查、名称/编码检查、快照最新日检查和主明细一致性检查。
5. 错题自动聚类为映射、口径、权限、SQL、空结果、数据质量、展示七类，再决定修注册表、修规则或修提示词。

### 4.3 智能

1. 先分类：指标查询、对比、归因、趋势、异常、实体、单据、明细、知识库、跨源；不同类型使用不同分析合同。
2. 深度模式采用候选计划 + 规则审查；必要时让第二次 precise 调用只做证据审查，不重新生成 SQL。
3. 经验分三层：个人偏好、团队验证经验、系统硬规则；只有系统硬规则和已审核团队经验能影响 SQL。
4. 支持“为什么”“怎么算”“换个维度”“只看某客户”等连续追问，继承的是语义状态，不是拼接上一轮原 SQL。
5. 主动分析只在有确定证据时给出异常、驱动和建议；不把普通波动包装成结论。

### 4.4 美观

1. 深度页固定信息层级：结论 KPI -> 同比/环比/目标 -> 趋势 -> 构成/排名 -> 驱动/异常 -> 明细 -> 口径 -> AI 收尾。
2. 使用图表选择器：时间用折线，排名用横条，占比仅在类别少且总量完整时用环图，相关性用散点，流程用漏斗。
3. 图表必须有单位、时间范围、数据标签、空值说明、TopN/其他项和可点击下钻；表格支持排序、筛选、冻结列、分页。
4. AI 文本在首屏占比不超过 25%；默认每组最多三条，每条必须包含数值或证据引用。
5. 建立桌面、DMS iframe、移动端、企微四套视觉回归截图；不允许文字重叠、暗色低对比和容器溢出。

### 4.5 速度

1. 为 graph/direct/entity/cache/LLM/deep 分别设预算，`query_log.steps` 展示每阶段 p50/p95 与超时原因。
2. 增加结果集缓存，key 必须包含 SQL 指纹、`ds_id`、权限指纹、指标版本和数据新鲜度；任一项变化即失效。
3. 元数据、字典、VQR、热门实体前缀启动预热；Doris 查询使用分区裁剪、谓词下推、合理 TopN，禁止无界明细。
4. 深度模式先返回主 KPI 与计划，再并行填充图表和明细；AI 分析最后异步补齐，失败不影响报表数据。
5. 增加请求取消、数据库 query timeout、LLM timeout 和断路器；切换会话不能取消后台任务，用户主动取消才停止。

## 5. 代码与数据落点

| 现有模块 | 本轮新增职责 | 边界 |
|---|---|---|
| `crates/kernel` | `TrustEnvelope`、语义 IR、可信分级与 ReportSpec 纯类型/纯校验 | 零 IO、零 DMS 业务词，不计算权限 |
| `crates/semantic` | 指标版本、允许维度、VQR、实体/单号注册、Join Graph 证据、质量规则 | 继续是业务语义唯一事实源，不依赖 policy |
| `crates/policy` | 可稳定序列化的权限指纹、分享校验所需 scope 摘要 | 不出现指标和报表逻辑，保持与 DMS 权限等价 |
| `crates/agent` | 问题分类、AnalysisPlan、证据审查、澄清/恢复状态 | 所有业务取数仍调用统一 answerer/`ask()` |
| `crates/connector` | 查询取消、超时、结果新鲜度、Doris 执行统计 | 不接受未经闸门的 SQL，不写业务源 |
| `crates/server` | 质量看板、反馈 API、checkpoint 编排、权限感知结果缓存 | 协议和装配，不新增第二套口径 SQL |
| `web/src` | 可信状态条、语义确认卡、反馈、渐进报表、证据引用、跨端布局 | 只渲染后端 ReportSpec，不在前端计算业务指标 |
| `meta.metric` | 增加版本、生效期、负责人、允许维度、质量状态 | 原表扩展，不复制指标表 |
| `meta.sql_exemplar` | 增加审核/验证/失效字段，承担 VQR | 原表升级，不新增 verified-query 平行表 |
| `meta.query_feedback` | 新表：反馈类型、trace、指标版本、处理状态 | 只保存诊断元数据，不保存密钥和敏感结果全文 |

结果集缓存优先使用进程内有界缓存；只有多实例部署证明需要共享缓存时才引入外部缓存。DMS 三个源码仓只用于抽取和校验元数据，仍保持只读。

## 6. 北极星指标

| 指标 | 计算方式 | 目标 |
|---|---|---|
| P0 执行准确率 | 黄金问题最终数值、维度集合、主键集合均正确 | 100% |
| 扩展执行准确率 | 非 P0 黄金问题执行结果正确 | >= 95% |
| 歧义误答率 | 应澄清却直接给出错误确定答案的比例 | < 1% |
| 可信凭证覆盖率 | 非闲聊结果带完整 TrustEnvelope 的比例 | 100% |
| 权限事故 | 跨账号、跨角色、跨会话、跨分享越权 | 0 |
| 深度证据覆盖率 | AI 结论可关联 KPI/图表/表格证据的比例 | 100% |
| 报表完整率 | 深度页满足 KPI、比较、两个分析、明细、口径、AI 收尾 | >= 95% |
| 确定性查询延迟 | 线上 p95 | < 1.5s |
| 深度首数据时间 | 主 KPI 可见 | < 2s |
| 深度完整报告延迟 | 线上 p95 | < 25s |
| 可复现率 | 同身份、同版本、同新鲜度重复执行得到一致结果 | >= 99.5% |

## 7. 分期实施

### Phase 0：质量控制面（第 1 周，P0）

- 基于 `query_log/correction_log/failure_log` 做质量与性能后台：路由、成功率、p50/p95、token、修复轮次、错题分类。
- 增加 `meta.query_feedback`，反馈与 `trace_id/conv_id/metric_version/sql_fingerprint` 关联。
- 建立 20 个 P0 指标、20 类单号、50 个高频实体和权限矩阵基线。
- 验收：100% HTTP/CLI/企微请求可追踪；一次错答可从界面定位到理解、SQL、权限、结果和报告阶段。

### Phase 1：可信答案与 VQR（第 2-3 周，P0）

- 落地 `TrustEnvelope`、三档可信标识、数据新鲜度、口径版本与 SQL 指纹。
- 将现有 approved exemplar 升级为 VQR，增加审核人、验证时间、执行环境和失效检测。
- 增加反馈复核页和“从正确回答沉淀 VQR”的受控流程。
- 验收：P0 指标全部显示可信凭证；VQR 变更必须自动重跑黄金集；跨账号与缓存越权为 0。

### Phase 2：语义编译与实体解析（第 4-6 周，P0）

- 指标版本、允许维度、递归派生、Join Graph 基数/条件、实体与单号注册表落地。
- 深度扫描 DMS 后端源码和 Doris 元数据，形成“表 -> 领域 -> 单据 -> 明细 -> 状态 -> 负责人”图谱并审核发布。
- 实现候选映射评分和结构化澄清；低可信不再生成看似确定的答案。
- 验收：P0 业务执行准确率 100%；扩展黄金集执行准确率 >= 95%；单号类型 Top20 识别与主明细定位 100%。

### Phase 3：深度 Agent 2.0（第 7-9 周，P1）

- `AnalysisPlan/ReportSpec`、问题分类合同、证据引用、自审、checkpoint、取消/恢复、选择卡统一落地。
- AI 只做计划和证据化解读，所有数值来自已执行结果。
- 会话 A 后台执行、切到 B、再返回 A 时状态和结果完整保留。
- 验收：深度报告每页至少包含主 KPI、一个比较、两个关联分析、一个明细证据和 AI 收尾；无证据结论为 0。

### Phase 4：BI 体验与三端一致（第 10-11 周，P1）

- 建立统一报表组件与 artifact 主题；支持全屏、交互筛选、下钻、分享、下载、打印/PDF。
- DMS iframe 与独立 UI 共用 token/身份，不二次登录；企微使用同一 ReportSpec 生成适合窄屏的摘要卡和链接。
- 验收：四类视口视觉回归通过；首屏无文本墙；分享与下载内容、口径、权限提示一致。

### Phase 5：性能与持续进化（第 12 周起，P1/P2）

- 结果缓存、预热、渐进式返回、慢查询治理、供应商/模型 A/B、夜间自动回归和失败聚类。
- 经营日报使用已验证指标生成，异常才主动推送；预测和建议作为 P2，必须带区间与前提。
- 验收目标：确定性查询 p95 < 1.5s；缓存命中 p95 < 500ms；深度模式首个有效数据 < 2s、完整报告 p95 < 25s；服务错误率 < 1%。

## 8. 测试与发布门禁

1. **单元层**：时间、值域、实体格式、指标展开、图谱路径、可信分级纯函数测试。
2. **SQL 结构层**：权限、扇出、时间上限、编码等值、最新快照、敏感列、只读闸门。
3. **执行黄金层**：在只读 Doris 上比较数值、维度集合、明细主键和零行语义。
4. **会话 E2E 层**：登录、切会话后台继续、澄清恢复、预览/分享/撤销、DMS SSO、企微身份。
5. **视觉层**：桌面/移动/DMS iframe/企微截图与图表像素非空检查。
6. **性能层**：串行固定数据集，不在测量期间重建容器；记录路由和模型版本。
7. **安全层**：提示注入、跨账号、跨源、分享 token、缓存 key、日志脱敏、配置密钥扫描。

| Sprint | 交付 | 直接收益 |
|---|---|---|
| S1 | TrustEnvelope + 反馈入口 + 质量看板 | 用户知道数据为什么可信，开发能定位错在哪里 |
| S2 | VQR 审核闭环 + 指标版本/允许维度 | 高频问法稳定复现，口径变更可追踪 |
| S3 | 单号/实体解析器 + DMS 源码图谱增强 | 输入任意单号或名词时准确找到主表、明细和关联信息 |
| S4 | AnalysisPlan/ReportSpec + 渐进式深度报告 | 深度模式从“多文字”升级为有关联、有证据、可操作的 BI 页 |

实施顺序不能调换：没有 S1/S2 的可信与语义地基，直接强化深度 Agent 只会更稳定地生成漂亮错答。

## 10. 明确不做

- 不让 LLM 绕过 `ask()` 直接查询业务库。
- 不展示或存储模型私有思维链；只展示可核查的计划、阶段和证据。
- 不用更多长文本冒充深度分析。
- 不建立第二套指标、权限、图谱或分享系统。
- 不缓存缺少权限指纹、指标版本或新鲜度的数据。
- 不把其他 Doris 库的同名字段自动当成 DMS 口径。
