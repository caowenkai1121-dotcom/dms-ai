## 2. 三个项目里**尚未整合**且值得做的（按「静默程度」排，不按项目排）

### 🔴 最阴的一条：值不在码表 → 合法 SQL → 返 0 行 → 用户读成「本月没有这类客户」
上游对照：SuperSonic `SchemaCorrector.removeUnmappedFilterValue`。
**今天的形态**：LLM 在**已登记码表**的列上写一个不存在的中文值 →
SQL 合法、三段闸门放行、执行成功、**返 0 行**。无报错、无告警、route 正常、`caliber_note` 为空。
这是错答里最难发现的一族。
**本仓不该照抄上游的「删条件」**：删了会把「0 行」变成一个**更宽的错数**（裁决 二·N 有一次
「口径层把本来正确的 SQL 改错」的账）。本仓形态应是**判违规 + 回炉说明里列出合法取值**。
**前置条件可证**：autodiscover 注册的码列是完整枚举（`uniq.len() > 60` 即跳过）；
但 `seed_defs` 手写那批可能只写了部分取值 → **必须先给 `meta.value_map` 加来源列，只对可证全枚举的开火**，否则造假红。

### 下钻确定性重写 —— 关键洞见是「**不要写 AST 改写器**」
上游对照：SuperSonic `ChatQueryServiceImpl.queryData`（`replaceMetrics`/`replaceFilters`，全程不过 LLM）。
今天点「按省份 ↓」= 拼一句 `原问句 + 按省份` **从头重问** —— 把一次已经答对的查询扔回 LLM 路，
而**全部失败都在 LLM 路**（确定性路至今 0 失败）。
本仓的便宜做法：上一轮 `route=direct-agg` 时**直接再调一次 `compose_sql_with`** ——
天然过表级口径/快照/扇出/残留守卫那几道门，不必新写改写器。
只覆盖 direct-agg 那 8-10 题；LLM 路显式回落到今天的重问（「点了没反应」比「重问」更糟）。

### 推荐维度的正确来源：**指标自己声明的可下钻维度**
上游对照：`DimensionRecommendProcessor` + `MetricDrillDownChecker`。
上游的关键设计不是「有个池子」，而是**推荐来源 = 该指标声明的下钻清单**，所以每条建议**天生可答**。
这正是我上一份计划那句警告（加宽 `DIM_POOL` 会把下钻按钮接到失败集上）缺的那一层。
今天 `DIM_POOL` 是 6 个常量、与指标无关、无排序。

### 追问改写从两槽变五槽 + **失败轮跳过**
上游对照：`NL2SQLParser.rewriteMultiTurn`（五槽 + `histSQL` 空则跳过 + 只取最近一条 **SUCCESS**）。
今天只喂「上一轮问句」，而上一轮真正的口径（哪张表、哪个时间列、哪个过滤）全在上一轮 SQL 里；
上一轮**失败**时今天照样改写，把用户往同一个坑里带并白烧一次 fast 调用。

### 指标召回降档（四档递进的最小版）
上游对照：`MapModeEnum` + `BaseMatchStrategy.getThreshold` + `AllFieldMapper` 兜底。
本仓指标召回是**单向子串**：差一个字整条口径卡就消失 → 落 LLM 裸猜。
而 `why-not-compose` 最大一档正是「①指标不命中」。同一个 miss 还连带**分诊**判错。
只做「严格档零命中才降档」+ 降档结果一律再过 `map_filter`。

### 回炉时把全量口径卡也喂进去
上游对照：`AllFieldMapper` / `MapModeEnum.ALL`。
今天 `repair()` 只给 schema 段 —— 而首轮失败最常见的原因恰恰是「口径卡没召回到」，
于是回炉把唯一的补救机会浪费了。全部声明也就 15 指标 + 10 维度，个位数 KB。

### 码值裸码回显
上游对照：SuperSonic `DimValueAspect` 的后半程（查询后 techName→bizName）。
本仓只为省份硬写了一份 34 码常量表；`meta.value_map` 里其余码值（`invoice_status`/`customer_class`/`paid_way`…）
在结果表里就是 `'2'`/`'04'` 这种裸码，用户得自己猜。

## 3. 四个可选方案（择一或组合）

### A · 先让静默的错答变得能红（**防错答，不追分**）
2-3 天。立场：本轮风险重心不是少答对一题（抖动池 ≥9/38，±2 量不出来），
而是三条「答错了但每个信号都说没错」。三条判据全落单测/回归层，**不吃评测抖动**。
- `check_caliber` 加状态格 + `guard::Verdict` 第四支（**照返 + 标注，不做成拒绝**，遵裁决 二·G）
- 复合问句里失败的子问不再连问句都不留（点名缺了哪一条）
- **值不在码表 = 违规**（新口径变体，同批给 `meta.value_map` 加来源列）
- （可选）LLM HTTP 错误分档 + 只给 `generate_sql` 一层 ≤1 次重试
**能量到**：单测 535 → 约 +10；回归 56 → 58；`query_log.error` 从「全是 Transport 一档」变成可分档。
**量不到**：38 题分数 —— 这一趟做的是「错答不再静默」，不是提分。

### B · 压 `why-not-compose` 的门分布（**追结构指标，不追分**）
3-5 天。立场：单轮分数量不到，但**门分布量得到**。只压两档：「①指标不命中」与「下钻建议接到失败集」。
**顺序纪律优先于工作量** —— 顺序反了就把飘着的失败换成确定的失败。
1. 先给 E09（按品牌）/E17（按客户分类）钉 `route: direct-agg` —— **今天必红，这就是反向验证**
2. 修 compose 让它们装得上（唯一的不确定项）
3. 下钻来源改成 `meta.metric.drill_dims`，排序用 `query_log` 的 LIKE 计数（不新建统计表）
4. 指标召回降档（先只做反向包含 + 长度阈值，**零新增依赖**）
**能量到**：「①指标不命中」档下降**且其余各档不许上升**；确定性可装配 ✅13 → 15-16（可数，不是分数）。

### C · 把已经存下来的素材接上（**智能 + 美观**）
3-4 天。立场：两处「素材已经躺在库里/结果里，没人读」。
- CLI `ask` 开 `prev` 参数（下游函数签名本来就有这个形参）+ `regression.py` 白名单加 `prev`
- 追问改写两槽 → 五槽 + 失败轮跳过（源是 `chat.msg.payload->>'sql'`）
- `Block::Chart` 加 `series`（只加 `Option`，不改现有键）→ 「时间 + 恰 1 类别 + 1 指标」三列结果
  从**必错**变成 0（今天任何该形态的结果都画成一条混轴折线）
- （可选）码值裸码回显
**能量到**：回归 56 → 58-59；混轴折线那一族从必错变成 0（可数）。
**量不到**：追问准确率 —— 55 题里今天 0 道两轮题，**没有历史基线可比**。

### D · 外围可用性与可归因（**不动答题链路的任何裁决面**）
1-2 天，风险最低，可与 A/B/C 任一并行。
- MCP 执行失败与协议失败分开（⚠️ **对外契约变更，要你先点头**）
- 分阶段归因：`query_log` 加 stage + 只读端点（「哪一段把口径带偏了」从翻容器日志变成一条 SQL）
- 输入联想 `/api/suggest`（打 `meta.element`，复用 ds 谓词与 visibility 总闸）
- （可选）`SelectCorrector`/`HavingCorrector` 两个语法位
**量不到**：38 题分数与 p95 都不会动（D 全部与答题链路正交）。

## 4. 明确不做（每条都有理由，别再翻案）

| 不做 | 核心理由 |
|---|---|
| DataSet 逻辑表 / S2SQL 中间层 / Calcite | 触发条件是 `direct-agg ≥ 19/38`，今天 17/38 未达。且判据只能写成「prompt 字符数下降 X% 且不降分」—— 测的是天花板不是当下红题。本仓 `try_compose` 已是这条路的最小版本，扩它更便宜 |
| 推荐追问 | 已**三次**判推迟（二·K6 + PROGRESS + 二·AN3 刚删掉计划里给它排的 3 天） |
| 多工作空间隔离 | 会让 46 条权限断言与 semantic-cache 指纹全部跟着改，写不出便宜判据 |
| Plan 状态机 / Reply 信封 | 已明确拒抄。给 0 触发的路径新建结构 |
| HITL / interrupt | **没有可门控的对象**：AST 层只放行 `Statement::Query`、连接级只读兜底、行权限走 `kernel::inject` 而非 LLM 改写。翻案触发条件：出现第一条真会产生副作用的能力 |
| 可覆盖 prompt / 每点独立模型配置 | 与既有安全属性**直接冲突**：prompt 一旦可被配置覆盖，那批 golden 断言就不再说明生产行为 —— 正是本仓最忌的恒真判据一族。真要换档是改一行 `ModelTier` 常量 |
| 多候选解析交给用户选 | **写不出判据**：「什么算歧义」在本仓没有可判定义（Router 是有序表、第一个接住即返回，无 score、无候选列表）。第一步应是先造出「歧义度」这个可测量的量，而不是先造 UI |
| 会话摘要压缩 / 上下文卸载 | **要压缩的东西不存在**（多轮只有一句改写）；卸载那一半本仓已有。今天没有任何一条失败指向 prompt 超预算 —— 为它写代码是给不存在的 bug 打补丁（二·AN3 刚犯过一次同类） |
| 上游的「删条件」与「自动补默认时间窗」 | 一律只做判据、不做改写。删未映射条件会把 0 行变成更宽的错数；自动补窗口是静默改数字 |
| dashboard / 存 SQL 重跑 | 存下来的 SQL 里烤着建卡人的 `employee_id IN (…)`，重跑必须按当前 viewer 重新注入 —— 本仓最大的越权面之一 |
| 按人的列权限 | 真成本不是删字段，而是 semantic-cache 必须同批加 principal 指纹，否则 A 的缓存答案回给 B = 越权 |
| 行权限通用 DSL | 新 DSL = 新的 fail-open 面。只有真接第三个源、且其行权限不是「客户码/业务员」形状时才划算 |
| 硬拦裸 `SELECT *` | 会撞既有正例与上传表路径。提示词可以加两行，但**有效性只能采样测、写不出能红的判据** |
| 指标引用指标递归展开 | 判据能红，但今天 **0 条失败指向它**。等第三条二阶派生指标出现 |
| 图表 `title` 字段 | 「title 非空」是恒真判据一族 |

## 5. 需要业主裁决的六件（不裁则相应条目不动）

1. **MCP 对外契约要不要变**（挡住 D1）：改成 `200 + isError:true` 后，已按 `-32000` 分支接的对接方
   会突然收到 200。二选一：批契约变更，或走退化版「`-32000` 拆成可重试/不可重试两个码」（不动响应形状）。
2. **手写码表哪些列是完整枚举**（挡住 A 的第三条对生产开火）：`meta.value_map` 今天没有来源列，
   而它有三种来源（手写 / autodiscover 字典匹配 / 名称型探针，后者**会截断**）。
   默认只对可证全枚举那批开火；要覆盖手写那批需要 DBA 逐列确认。
3. **`item_type` 取 '1' 还是 '3'**（二·J′，实测 204.5M / 208.1M / 131.4M，至今未裁决）：
   它压着「解除 `agg_template` 让路门」，而那是确定性覆盖再往上走的前提。**方案 B 的天花板由它决定。**
4. **SALE15 的业务口径**：不裁决就永远是剩余 2 红里的 1 红 —— 任何「提了几题」的说法都要先扣掉它。
5. **「必须带时间下界」的指标清单**：没有这张表，时间下界判据只能默认全关
   （否则「总销售额（有史以来）」这类合法问句会被判违规）。
6. **prompt 全文是否允许落盘**（挡住 D2 的一半）：存档内容含结果集与 schema，落盘即扩大数据面。
   要与「明文 DSN 不进日志」同口径（存前脱敏），或者只存阶段 token 与 kind、不存正文。
